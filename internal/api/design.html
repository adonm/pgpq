The model in three ideas

Everything is immutable.Features live in FlatGeobuf chunks, one catalog row per chunk. A load writes new files and new rows, and never edits old ones.
Partitions are the unit.Every feature belongs to one S2 level-8 cell, about 36 km across. Loads and replacements work on whole partitions. Reads find chunks by key range.
Overviews are capped samples.A cell keeps at most 256 features: the ones with the smallest hash of their id. Coarser levels are built from finer ones, so one rule holds at every zoom.

Level ladder

Bar length follows log cell size. Each level keeps at most 256 features per cell, so a finer level shows more features on screen.

Detail (every feature) sits below the finest level, in chunks. The client picks a level with overview=N. The server does not map zoom to level.

Why level 12 exists

Estimates for a dense partition (about 1,900 features per km², from the design's density figures) on a 1024×768 screen at 48°N. Measure on buildings_fr before trusting the numbers.

Detail is too large to draw at these zooms, and level 10 alone is too sparse at 14 and 15. Level 12 covers that gap, and only for dense partitions, so the storage cost stays small.

Load: one request, one snapshot

1 · STREAM
Read the body. Canonical ids and geometry checks. 422 for duplicate ids, bad geometry, or features outside the listed cells.
→
2 · BUCKET
Group features by level-8 partition, in memory. Spilling to disk is not built.
→
3 · WRITE BLOBS
In parallel: detail chunks, samples at levels 8 and 10, level 12 for dense partitions, and the id run. Blobs are immutable and written before the commit.
→
4 · COMMIT
One transaction: lock the collection, end replaced rows, insert new rows at snapshot s, rebuild levels 6, 4 and 2 from the children at s, publish the files.

PUT ?base=s fails with 409 if any listed partition changed after snapshot s.

Storage

files, blocksImmutable files in 8,120-byte rows, in schema pfgb.
chunksOne row per chunk: partition, level, seq, first and last (key, id), envelope, rows, file ids, zone map JSON, begin and end snapshot.
partitionsLast changed snapshot per partition. Used by base=.
id_runsOne run per load: sorted (hash of id, key) pairs. Live until a whole load replaces it.
snapshots, collectionsSnapshot times, for 72 h retention. Current snapshot and schema per collection.
CachesThree LRUs per worker, 256 MiB each: file bytes, chunk lists per snapshot, decoded id runs.

Glossary

KeyThe S2 level-30 cell of a feature's bbox centre. Sets the storage order.
PartitionAn S2 level-8 cell. The unit of load and replacement.
ChunkAn immutable FlatGeobuf (zstd) with a column sidecar and a zone map, and one catalog row.
SampleThe 256 smallest-hash features of a cell, stored as chunks with level = N.
Zone mapPer-column min, max and null count for a chunk. Prunes filters.
Id runSorted (hash of id, key) pairs written with each load. Used by lookups.
SnapshotOne load's commit. A row is visible at snapshot s when begin ≤ s < end.
base=The snapshot a loader read. The load fails if a listed partition changed since.
